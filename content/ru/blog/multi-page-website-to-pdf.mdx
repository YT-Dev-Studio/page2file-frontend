Многостраничный сайт следует конвертировать как ограниченную коллекцию, а не как бесконечный crawl. [GPT-приложение Web 2 PDF](/ru/web2pdf-gpt) находит доступные страницы целевого сайта, отправляет каждый выбранный открытый URL на конвертацию и возвращает несколько PDF для скачивания.

Оно не объединяет весь сайт в один документ без контроля. Каждая страница сохраняет собственную границу источника и отдельный файл, поэтому ошибки и разрешения проще проверять.

## Определите границы сайта

Начните с host и раздела, который должен войти в коллекцию. Решите, включать ли языковые версии, архивы, результаты поиска, теги и дубли с query string. Внешние домены остаются ссылками и не становятся новыми целями обхода.

Sitemap подсказывает список страниц, но не доказывает, что каждый URL нужен. Уберите административные маршруты, аккаунты, дубли фильтров и материалы, которые нельзя воспроизводить.

## Сохраняйте отдельный файл для каждой страницы

Отдельные PDF сохраняют заголовки уровня страницы и показывают, какой URL завершился ошибкой или redirect. Ошибка одной страницы не делает бесполезным весь экспорт сайта.

Если получателю нужен единый пакет, скачайте проверенные PDF и объедините либо заархивируйте их подходящим инструментом. Web 2 PDF возвращает несколько файлов и не обещает идеальный единый документ сайта.

## Учитывайте различия шаблонов

Один сайт может сочетать статьи, каталоги товаров, дашборды и встроенные медиа. Выбирайте Accurate copy — режим точной визуальной копии или Editable document — режим редактируемого документа по цели коллекции и проверяйте предупреждения о шрифтах, изображениях и ссылках. Классифицировать источники поможет [руководство по типам сайтов](/ru/blog/website-types-to-pdf-or-powerpoint).

Закрытые разделы не обнаруживаются публичным обходом. Разрешённую страницу после входа сохраняйте через [расширение](/ru/chrome-extension/how-to-use), по одной активной вкладке.

## Проверьте коллекцию перед передачей

Проверьте список URL, заголовки, дубли, redirects, первую и последнюю страницу каждого PDF. Для отдельных длинных источников используйте [проверку разрывов](/ru/blog/long-webpage-page-breaks).

Экспорт сайта остаётся копией опубликованного материала. Соблюдайте robots guidance, условия источника, авторские права и ограничения частоты; не используйте конвертацию для обхода доступа.

## Составьте явный список страниц

Начните с URL и причины включения каждой страницы. Навигация и sitemap помогают находить публичные адреса, но не доказывают, что все они нужны. Исключите дубли print-view, tracking variants, search results и страницы вне выбранного раздела.

Нормализуйте slash, fragments и campaign parameters. Языковые версии сохраняйте только намеренно. Отдельно отметьте страницы с login или пользовательским действием: Web 2 PDF работает с доступными публичными страницами и не обходит контроль доступа.

## Сделайте коллекцию понятной

Результат — отдельный PDF для каждой страницы, поэтому нужны стабильные имена и простой index. Не полагайтесь на порядок скачивания: задачи могут завершаться по-разному.

В index укажите исходный URL, дату, имя файла и статус проверки. Это карта набора, а не обещание одного объединённого документа. Если нужен единый сборник, объединяйте только принятые PDF и зафиксируйте новый порядок.

Сохраняйте provenance каждой страницы. Сайт может обновить один документ, не меняя остальные; повторный экспорт всего раздела не всегда нужен.

## Проверяйте шаблоны и исключения

Откройте по одному представителю каждого шаблона: homepage, article, docs и product page. Обрезанная навигация или отсутствующий шрифт обычно повторятся во всём типе.

Затем проверьте длинные таблицы, galleries, charts и redirects. Каждый PDF должен иметь ожидаемый title, начинаться с нужного контента и не содержать login wall.

В конце количество принятых файлов должно совпасть со списком URL, а у каждого исключения должна быть причина.

## Ограничьте обнаружение страниц

Начните с навигации, sitemap и внутренних ссылок нужного раздела. Это подсказки, а не команда бесконечно обходить все URL. Календари, фильтры и поиск могут создавать неограниченное число вариантов.

Заранее задайте host, path, язык и правила query-параметров. Web 2 PDF находит доступные страницы и создаёт отдельные файлы; его нельзя описывать как crawling API или парсер структурированных данных. Redirect и JavaScript-навигацию фиксируйте отдельным статусом.

## Выберите режим для коллекции

Editable document подходит статьям и документации, визуальный — дизайн-референсам и дашбордам. Если сайт смешанный, сгруппируйте страницы по шаблону и объясните исключения. Проверьте представителя каждого шаблона до обработки всей коллекции.

## Не теряйте ошибки из списка

Недоступный URL, redirect loop, удалённая страница или предупреждение должны остаться в журнале. Повтор помогает только после изменения условия; приватный маршрут или отсутствие прав он не исправит.

Сверяйте каждый URL с именем файла и статусом. PDF с consent wall или страницей ошибки не считается успешным только потому, что скачался. Закрытые страницы сохраняйте отдельно из разрешённой активной вкладки.

## Подготовьте пакет

Используйте уникальные имена и manifest с URL, title, датой, режимом и результатом проверки. Если нужен объединённый PDF, сначала утвердите отдельные файлы, затем объедините их другим инструментом и проверьте новый порядок.

Укажите границу коллекции и исключения. Формулировка «английская документация на эту дату без закрытых страниц и дублей» точнее, чем «весь сайт».

## Обновляйте коллекцию как новый снимок

Сайты меняются по частям. Сохраните предыдущий manifest, чтобы отделить добавленные, удалённые и изменённые страницы. Каждый PDF фиксирует состояние на дату захвата и не синхронизируется с URL.

Данные предпросмотра удаляются после закрытия вкладки, а Page 2 File не ведёт историю конвертаций. Храните утверждённые файлы и manifest самостоятельно.

При следующем запуске применяйте те же правила границы и отдельно отмечайте страницы, которые изменились после предыдущей даты проверки.

Перед передачей откройте архив и исключите черновики, ошибки и служебные заметки.
