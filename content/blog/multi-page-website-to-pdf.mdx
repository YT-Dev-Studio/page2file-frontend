A multi-page website should be converted as a bounded collection, not as an unlimited crawl. The [Web 2 PDF GPT App](/en/web2pdf-gpt) finds accessible pages on the target site, sends each selected public URL for conversion and returns several PDF files for download.

It does not silently merge the whole web into one document. Each page keeps its own source boundary and output file, which makes failures and permissions easier to review.

## Define the website boundary

Begin with the host and the section that belongs in the collection. Decide whether language variants, archives, search results, tag pages and query-string duplicates should be included. External domains remain links rather than becoming new crawl targets.

A sitemap can suggest pages, but it does not prove that every URL belongs in the export. Remove admin routes, account pages, duplicate filters and anything you do not have permission to reproduce.

## Keep one page per output job

Separate PDF files preserve page-level titles and make it clear which URL failed or redirected. They also avoid one broken page invalidating an otherwise useful website export.

If a recipient needs a single package, download the reviewed PDFs and combine or archive them with an appropriate document tool. Web 2 PDF itself returns multiple files rather than claiming one perfect merged website document.

## Expect differences across pages

A site can mix article templates, product grids, dashboards and embedded media. Choose screenshot or editable output according to each collection's goal, and inspect font, image and link warnings. The [website types guide](/en/blog/website-types-to-pdf-or-powerpoint) helps classify these sources.

Authenticated areas cannot be discovered by a public crawl. Capture an allowed signed-in page with the [extension](/en/chrome-extension/how-to-use), one active tab at a time.

## Review before distributing

Check the URL list, titles, duplicate pages, redirects and the first and last page of every PDF. For individual long sources, apply the [page-break review](/en/blog/long-webpage-page-breaks).

A site-wide export is a copy of published material. Respect robots guidance, source terms, copyright and rate limits, and do not use it to bypass access controls.

## Build an explicit page inventory

Start with a list of candidate URLs and the reason each page belongs. Navigation, sitemaps and internal links can help discover public pages, but discovery is not proof that every URL should be exported. Exclude duplicate print views, tracking variants, search results and pages outside the intended section.

Normalize obvious variants before conversion. A trailing slash, fragment or campaign parameter can point to the same content while appearing to be a separate page. Keep language and regional variants only when they are intentionally part of the collection.

Record pages that require login, consent or a user action. Web 2 PDF works with accessible public pages; it does not bypass access controls. Capture authorized private pages from their active browser tabs as a separate workflow.

## Keep the collection navigable

Because the result is one PDF per page, filenames and a simple index matter. Use a stable naming pattern that identifies the source section and page title. Avoid relying on download order, which can change when pages finish at different times.

An index can contain the original URL, capture date, output filename and review status. That gives a recipient a map without pretending that separate files are one merged book. If a combined publication is required, merge only after the individual PDFs have passed review and document the new reading order.

Keep page-level provenance. A website can update one page without changing the others, so a collection assembled on different dates should say so. Re-running the whole site may be unnecessary when only a small subset changed.

## Review patterns and exceptions

Check representative pages from each template: the homepage, article, documentation page, product page and any unusual layout. Template-level defects such as clipped navigation or missing fonts are likely to repeat and should be fixed before reviewing every file.

Then inspect page-specific risks. Long tables, image galleries, embedded charts and short redirect pages can fail even when the template looks correct. Verify that each PDF has the expected title, begins at the intended content and contains no authentication error or cookie wall.

Finish with reconciliation: the accepted-file count must match the reviewed URL inventory, and every exclusion should have a reason. This prevents a convenient download folder from being mistaken for a complete website archive.

## Choose a discovery method without promising a crawl

Start from the website’s visible navigation, declared sitemap and internal links that belong to the requested section. These are discovery signals, not an instruction to follow every URL indefinitely. Calendars, faceted filters and generated search pages can produce effectively unbounded address spaces.

Set explicit rules before discovery: allowed host, path prefix, language, maximum scope agreed for the task and treatment of query parameters. Stop when a candidate falls outside those rules. Web 2 PDF is described as finding accessible pages and producing separate files; it should not be represented as a crawling API or structured-data scraper.

Some pages may be reachable only through JavaScript navigation and some sitemap entries may no longer work. Record them as discoveries with a status, then decide whether they belong. Do not substitute a redirect target silently when it changes the subject or crosses the approved boundary.

## Select output mode for a collection

A consistent mode makes a collection easier to use, but a website can contain several document types. Editable output is a strong default for articles and documentation because supported text and links remain useful. Screenshot output is better suited to design references, dashboards and pages where composition carries the meaning.

If the collection mixes those types, group pages by template or purpose and document the selected mode for each group. Avoid changing modes page by page without a rule; recipients should be able to understand why one file is searchable while another is image-based.

Preview representative pages before processing the full inventory. Check one ordinary page and every unusual template. A repeated navigation defect or missing font should be addressed at the pattern level before it appears in dozens of files.

## Handle failures without losing the inventory

An inaccessible URL, redirect loop, removed page or rendering warning should remain visible in the review record. Retrying can help when a transient resource failed, but it cannot fix a private route or a page you are not authorized to access. After a changed attempt, mark the page accepted, excluded or blocked with a reason.

File count alone is not proof of completeness. Reconcile each candidate URL against an output filename and status. Check for duplicate titles, empty error pages and PDFs that contain only a cookie or access notice. A technically downloadable file may still be a failed conversion.

For signed-in material, leave the public collection workflow. Open each permitted page in Chrome and use active-tab capture. The preview is temporary, is deleted when its tab closes and is not retained in a Page 2 File conversion-history database. Private pages should not be added to a public discovery list.

## Package the reviewed result

Use filenames that remain unique when page titles repeat. A short path-derived identifier can distinguish two “Overview” pages without exposing sensitive query parameters. Keep a separate manifest with source URL, title, capture date, selected mode, output filename and review result.

Organize the PDFs in the intended reading order only after every page has been reconciled. If recipients need one combined PDF, merge the accepted files with a suitable tool and verify the combined bookmarks, page order and boundaries. That merged artifact is a separate editorial result; Web 2 PDF itself returns one PDF per discovered page.

Before delivery, sample links and page breaks from each template and open every file that had a warning. State the scope and exclusions alongside the collection. “Documentation section captured on this date, excluding private account pages and duplicate language variants” is more useful than “entire website” when the boundary was narrower.

## Maintain the collection over time

Websites change unevenly. A new navigation item may add a page, an old URL may redirect and a single article may be revised while the rest stay stable. Preserve the earlier manifest so a later run can identify additions, removals and changed sources rather than rebuilding an unexplained folder.
