A conversão de HTML em PDF transforma um ficheiro HTML fornecido num documento fixo. Com a [HTML 2 PDF GPT App](/pt/html2pdf-gpt), a entrada é o ficheiro que fornece, não um rastreio de URL nem o estado autenticado de um separador.

Trate todos os ficheiros HTML como código ativo até um renderizador provar o contrário. Um design de conversão defensável restringe scripts e acessos de rede inesperados, bloqueia pedidos a ficheiros locais e serviços internos e torna o conteúdo não suportado visível para revisão. Não deduza estes controlos de um PDF bem apresentado; verifique o limite documentado do conversor antes de fornecer dados sensíveis.

## Prepare um ficheiro autónomo

Utilize títulos semânticos, parágrafos, listas e tabelas. Inclua o CSS necessário para o layout e agrupe as imagens numa forma que a entrada aprovada consiga resolver. Um ficheiro dependente de um servidor de compilação privado ou API autenticada não será reproduzido com fiabilidade num renderizador isolado.

Remova análise, envio de formulários, reprodução automática e código que altere o documento após o carregamento. O PDF é um destino estático; manter estes comportamentos aumenta o risco sem melhorar o documento.

## Mantenha o renderizador isolado

HTML não fiável pode tentar ler ficheiros locais, chamar endereços internos ou consumir recursos excessivos. A conversão deve executar num processo separado e restrito, com scripts, WebSockets e pedidos arbitrários de rede desativados.

O isolamento pode mudar a aparência de conteúdo dependente de tipos de letra, imagens ou componentes remotos. Trate recursos em falta como conclusões da revisão em vez de assumir que uma renderização concluída está completa.

## Conceba para páginas fixas

Defina larguras de impressão sensatas, permita a quebra de palavras longas e código e evite elementos que requerem hover. As tabelas precisam de cabeçalhos repetíveis e células que possam dividir ou redimensionar sem ficarem ilegíveis.

Se a sua fonte real já for uma página pública, utilize o [conversor PDF de página Web](/pt/convert-webpage-to-pdf). Se for uma página privada visível no Chrome, utilize a [extensão](/pt/chrome-extension/how-to-use).

## Reveja o documento, não apenas o HTML

Verifique substituições de tipos de letra, imagens em falta, elementos posicionados cortados, quebras e ligações. Compare secções complexas com o guia de [capturas versus saída editável](/pt/blog/visual-vs-editable).

HTML 2 PDF é útil quando controla o ficheiro de entrada e pretende uma renderização isolada. Não é um endpoint de automação do navegador, scraper de sites nem forma de executar scripts fornecidos.

## Inventarie todas as dependências

Um ficheiro HTML raramente conta toda a história. O layout pode depender de folhas de estilo locais, tipos de letra Web, imagens, SVG, scripts ou recursos remotos. Identifique os recursos essenciais e como cada um é referenciado. Um ficheiro que parece completo no projeto original pode tornar-se uma coluna sem estilos quando aberto isoladamente.

Prefira estilos e recursos autónomos que o documento esteja autorizado a usar. Substitua caminhos apenas de desenvolvimento e referências de rede privada. Se for necessária uma imagem remota, verifique que está disponível sem sessão autenticada. Não se deve esperar que um conversor herde cookies da estação ou a estrutura do sistema de ficheiros.

Remova scripts que obtenham dados do utilizador, análise ou estado não relacionado da aplicação. HTML estático para PDF costuma precisar de menos execução do que o site original. Mantenha apenas o comportamento necessário para revelar o documento e confirme que o conteúdo final não depende de temporizador ou gesto.

## Torne explícitas as dimensões de impressão

Os layouts do navegador respondem a uma área visível, enquanto os PDFs usam dimensões fixas. Defina largura, margens e tipografia sensatas para o papel pretendido. Evite posicionar o documento principal com pressupostos de altura da área ou deixar texto importante em contentores de deslocamento horizontal.

Utilize regras de quebra como indicações em torno de títulos, figuras, tabelas e código e inspecione o resultado. As regras podem entrar em conflito quando um elemento é mais alto do que uma página. Uma tabela grande pode precisar de cabeçalhos repetidos ou orientação horizontal; um visual alto pode ter de permanecer uma imagem redimensionada.

Texto muito claro, camadas translúcidas e tokens exclusivos do modo escuro podem ser difíceis de ler na impressão. Verifique o PDF em vez de assumir que a pré-visualização do navegador representa todos os leitores e impressoras.

## Trate HTML carregado como entrada não fiável

Carregue apenas ficheiros que tem autorização para processar e remova segredos incorporados em marcação, comentários, atributos de dados ou scripts inline. Conteúdo oculto pode viajar com a fonte mesmo que não apareça na página final.

Um renderizador deve restringir a rede e o sistema local, mas o isolamento técnico não corrige escolhas inseguras. Reveja ligações externas, formulários incorporados e códigos QR gerados antes da distribuição. O PDF é estático, mas as ligações podem continuar a levar o destinatário para fora.

Compare o resultado com uma lista de dependências. Confirme tipos de letra, imagens, ordem, títulos, ligações e última página. Se faltar um recurso, corrija o pacote HTML ou utilize um URL público capaz de carregar a página completa.

## Separe riscos de autoria dos riscos de renderização

Os riscos de autoria já estão no ficheiro: segredos incorporados, dados pessoais ocultos, ligações enganosas e conteúdo que não tem permissão para distribuir. Os riscos de renderização surgem quando HTML ativo pode pedir recursos de rede, aceder a um local não pretendido ou consumir demasiado tempo. Um fluxo fiável precisa de controlos para ambas as categorias.

Inspecione a fonte antes do carregamento quando possível. Procure scripts inline, manipuladores de eventos, formulários, URL externos, caminhos locais e grandes recursos incorporados. Remova tudo o que não estiver relacionado com o documento. Isto reduz a ambiguidade mesmo quando o renderizador aplica restrições próprias.

Não utilize a conversão para descobrir se HTML desconhecido é seguro. Se o ficheiro veio de um remetente não fiável, siga primeiro o processo de malware e tratamento de documentos da organização. Um PDF resultante não torna retroativamente a entrada inofensiva.

## Crie HTML previsível para paginação

Utilize uma hierarquia lógica de títulos e mantenha a ordem principal no fluxo do documento. O posicionamento absoluto pode ser útil numa capa ou rótulo, mas usá-lo no relatório inteiro dificulta diagnosticar excesso em páginas fixas. Defina larguras explícitas para tabelas e media, máximos sensatos e permita a quebra de texto longo.

O CSS de impressão pode definir margens, tamanho e preferências de quebra, mas estas regras são pedidos, não garantias. Um elemento mais alto do que a página terá ainda de ser reduzido ou dividido. Mantenha legendas perto das figuras, repita o contexto de tabela quando suportado e evite explicações essenciais apenas em hover ou pseudo-elementos.

Os tipos de letra precisam de uma pilha alternativa. Um tipo remoto pode estar indisponível num ambiente restrito. Escolha uma alternativa com métricas semelhantes e verifique títulos, tabelas e código para mudanças de quebra. O tipo exato importa menos do que um resultado estável e legível, salvo se a tipografia for o tema.

## Reveja a saída como novo artefacto

Compare o PDF com um inventário de conteúdo, não apenas com a vista do HTML. Confirme que todas as secções aparecem uma vez, a ordem está correta, as imagens são atuais e as ligações apontam para destinos aprovados. Pesquise uma frase perto do início, meio e fim quando esperar texto selecionável.

Procure provas de dependências bloqueadas: molduras vazias, tipos alternativos, gráficos vazios ou lacunas onde deveria aparecer um componente gerado por script. Repare o pacote ou aceite uma alternativa documentada. Não esconda um elemento em falta só porque as páginas envolventes renderizaram.

HTML 2 PDF é apresentada como uma GPT App para um ficheiro HTML carregado e um resultado PDF. Não é um rastreador geral nem ambiente de execução de aplicações. Utilize o conversor de URL para uma página pública e a extensão Chrome para um separador ativo autorizado.

Antes da distribuição, verifique metadados, identificadores visíveis e alvos clicáveis. A renderização mais segura pode ainda conter informação colocada pelo autor. Guarde o PDF final aprovado no seu armazenamento porque o Page 2 File não fornece uma base de dados de histórico.
