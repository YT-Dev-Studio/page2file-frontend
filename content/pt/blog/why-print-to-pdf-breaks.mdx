Imprimir como PDF no navegador e converter um URL em PDF partem de versões diferentes de uma página. A impressão utiliza a folha de estilos de impressão do site quando esta existe. Um conversor pode trabalhar a partir do layout renderizado no ecrã e dividi-lo em secções que podem ser revistas. Nenhum método é automaticamente melhor; a página e o documento pretendido determinam a escolha.

## Porque o resultado impresso pode não se parecer com o ecrã

O CSS pode atribuir regras diferentes ao ecrã e à impressão. Uma folha de estilos de impressão pode remover navegação e anúncios, mas também pode ocultar fundos, alterar colunas, substituir tipos de letra ou esconder painéis interativos. Elementos fixos podem repetir-se em várias páginas. Um gráfico desenhado em canvas pode surgir como uma área vazia se o processo de impressão não capturar os respetivos píxeis.

Os conteúdos multimédia de carregamento diferido criam outra diferença. A impressão começa no estado atual do documento; o conteúdo que nunca entrou na área visível pode não existir nesse estado. As interfaces virtualizadas de chats e dashboards podem remover linhas antigas do DOM durante o deslocamento, o que significa que um comando de impressão não as consegue recuperar.

## O que muda na conversão por URL

Um conversor de URL público carrega o endereço num navegador controlado e prepara o resultado renderizado para PDF. Não herda a sua sessão pessoal, pelo que não consegue ver um dashboard privado nem uma página protegida por início de sessão. Este limite protege as credenciais, mas torna o método inadequado para material autenticado.

Para um separador privado, a [extensão Page 2 File](/pt/chrome-extension/how-to-use) captura a página que abriu após uma ação explícita. Não pede a palavra-passe da conta. Certifique-se de que os painéis e mensagens necessários estão visíveis antes da captura.

## Compare os ficheiros, não os nomes dos botões

Verifique se o texto pode ser selecionado, se as ligações continuam úteis, se os fundos transportam informação e se as quebras respeitam os títulos. Uma exportação por capturas costuma preservar melhor um layout difícil. Uma exportação editável torna o conteúdo suportado mais fácil de pesquisar e rever, mas pode rasterizar elementos complexos.

O guia de [capturas versus saída editável](/pt/blog/visual-vs-editable) explica esta escolha. Para fontes muito altas, reveja também o [guia de captura de página completa](/pt/blog/capture-full-webpage-as-pdf) antes de escolher um método.

## Uma decisão prática

Escolha a impressão do navegador para um artigo simples com uma boa folha de estilos de impressão. Escolha conversão de URL em capturas quando a aparência for importante, ou conversão editável quando o conteúdo tiver de permanecer pesquisável e com ligações. Escolha captura do separador ativo quando a fonte for privada, personalizada ou disponível apenas após interação.

A pré-visualização continua a ser a prova decisiva. Se faltar um bloco importante, não presuma que reaparecerá no PDF final.

## Execute uma comparação controlada

Compare ambos os métodos a partir do mesmo estado do navegador. Defina a mesma área visível, filtros, painéis expandidos e posição de deslocamento antes de criar qualquer ficheiro. Caso contrário, estará a comparar duas fontes diferentes e não dois métodos de conversão. Registe se a página terminou de carregar imagens, tipos de letra Web e gráficos.

Comece pela pré-visualização de impressão do navegador. Anote a navegação, fundos, painéis interativos e elementos fixos que desaparecem. Isto não é automaticamente um defeito: uma folha de estilos bem concebida pode remover o ruído e produzir a melhor cópia para leitura. A questão é saber se removeu algo necessário ao seu objetivo.

Inspecione depois a pré-visualização do Page 2 File no modo correspondente à tarefa. Accurate copy (saída em capturas) deve ser avaliado pela semelhança e legibilidade. Editable document (saída editável) deve ser avaliado pela ordem de leitura, seleção de texto, comportamento das ligações e qualidade das alternativas para componentes complexos. Comparar apenas o tamanho do ficheiro pouco diz sobre a utilidade de qualquer documento.

## Diagnostique diferenças comuns

Cor ou imagens em falta costumam resultar de CSS específico de impressão, das definições do navegador para gráficos de fundo ou de um componente que renderiza de forma diferente em media de impressão. Painéis truncados surgem frequentemente quando um contentor deslocável tem altura fixa ou quando o conteúdo virtualizado nunca entrou na página renderizada. Espaço vazio pode provir de cabeçalhos fixos, espaços reservados para anúncios ou regras de impressão que forçam uma quebra.

As tabelas expõem outra diferença. Uma folha de estilos pode repetir corretamente os cabeçalhos, reduzir a tabela até o texto ficar ilegível ou cortar colunas fora da largura imprimível. Uma captura pode preservar a tabela apresentada, mas não faz um layout largo caber naturalmente numa página vertical. A conversão editável pode reconstruir linhas e células normais e utilizar uma imagem alternativa para grelhas incomuns.

As ligações merecem uma verificação própria. Os PDFs gerados pelo navegador podem manter âncoras normais, mas um URL visível desenhado em canvas ou fornecido por um script pode não se tornar interativo. O Page 2 File Editable document mantém as âncoras suportadas; Accurate copy dá prioridade à aparência. Teste os destinos em vez de assumir que texto azul sublinhado é clicável.

## Escolha com base nas provas e no custo de manutenção

Para um artigo pontual com uma boa vista de impressão, a impressão do navegador costuma ser suficiente. Para um dashboard, aplicação autenticada, página dinâmica longa ou fluxo orientado para apresentações, os controlos de captura e pré-visualização podem importar mais do que as convenções de impressão do navegador. Nenhum método deve ser tratado como universalmente superior.

Se a mesma fonte for exportada regularmente, escreva os passos de preparação e as verificações de aceitação. Um procedimento estável é mais valioso do que escolher repetidamente uma ferramenta por intuição. Reveja-o quando o site alterar o layout, a autenticação ou o comportamento de virtualização.

Vídeo, animação, estados ao passar o cursor e controlos em direto não podem permanecer interativos num PDF comum. O resultado defensável é um registo legível de um estado definido da página com limitações conhecidas.

## Separe definições de impressão de problemas da fonte

Alguns defeitos podem ser corrigidos no diálogo de impressão do navegador. Tamanho do papel, orientação, margens, escala e definições de gráficos de fundo podem alterar substancialmente o resultado. Experimente estes controlos quando o conteúdo estiver presente mas mal ajustado. Não conseguem restaurar um painel removido pela folha de estilos de impressão nem mensagens que uma interface virtualizada nunca renderizou.

Os cabeçalhos e rodapés adicionados pelo navegador são outra opção específica da impressão. Podem fornecer URL e data, mas também podem revelar um endereço privado ou empurrar conteúdo para uma página adicional. Reveja-os deliberadamente em vez de aceitar o valor predefinido. Um conversor de URL tem outro modelo de pré-visualização e secções, por isso compare os metadados reais em cada ficheiro.

Não trate um tamanho de página maior como solução universal. A orientação horizontal pode ajudar uma tabela larga, mas torna um artigo estreito mais difícil de ler. Uma escala agressiva pode evitar cortes mas transformar rótulos e notas em texto ilegível. As condições previstas de visualização são mais importantes do que colocar tudo no menor número de folhas.

## Decida com uma matriz de fonte e tarefa

Para um artigo preparado pelo editor, a impressão do navegador é um primeiro teste sensato porque a folha de estilos pode já remover navegação e formatar citações. Para uma página de marketing ou referência de design, a conversão em capturas costuma ser melhor porque a composição do ecrã tem significado. Para documentação e notas de investigação, a conversão editável merece o primeiro teste porque importam pesquisa, seleção e ligações.

Dashboards e chats exigem outra pergunta: o estado necessário está realmente renderizado? Se não estiver, nem a impressão nem a conversão por URL o conseguem reconstruir. Carregue o intervalo autorizado, estabilize os filtros e utilize captura do separador ativo quando o estado depender de uma sessão autenticada. Nunca se deve esperar que uma tarefa por URL público herde essa sessão.

## Registe uma comparação defensável

Para exportações recorrentes, mantenha um pequeno registo de teste: URL de origem, estado do navegador, data, definições de impressão, modo do Page 2 File e defeitos encontrados em cada resultado. Capturas das duas pré-visualizações podem explicar por que motivo foi escolhido um método, mas não devem substituir a verificação do PDF final.

Avalie ambos os ficheiros com os mesmos critérios de aceitação:

- todo o conteúdo necessário aparece uma vez e na ordem certa;
- texto principal, rótulos de gráficos e código são legíveis com zoom normal;
- as ligações importantes funcionam e não revelam destinos sensíveis;
- títulos, legendas e contexto das tabelas sobrevivem às quebras de página;
- dados privados da conta ou espaço de trabalho estão ausentes, salvo se forem necessários.

Um método passa quando produz o documento necessário para esta fonte e tarefa. Se ambos falharem, reduza a captura, altere o estado da página ou utilize a exportação específica da plataforma de origem. Repetir o mesmo comando numa página instável não é uma estratégia de reparação.

## Volte a verificar depois de o site mudar

O comportamento de impressão e captura pode mudar quando um site atualiza o CSS, biblioteca de gráficos, camada de consentimento ou regras de virtualização. Um procedimento que funcionou no mês passado é prova sobre essa versão da página, não uma garantia permanente. Repita verificações representativas após uma reformulação e antes de uma distribuição de grande impacto.

Este ponto de manutenção é particularmente importante em rotinas aparentemente automáticas. O Page 2 File fornece uma pré-visualização porque o estado da página continua a necessitar de revisão humana. A pré-visualização pode revelar secções em falta e limites incómodos; não pode decidir se o documento está completo para o seu objetivo jurídico, arquivístico ou operacional.
