## Inclusion boundary

Include URL, HTML or rendered-webpage conversion to PDF/PPTX; visual and
editable output; long/full-page capture; authenticated browser tabs; AI chats;
browser-accessible messenger conversations; direct browser-page capture for
Instagram, Facebook, LinkedIn and Wikipedia; and the user-locked PDF definition
topic.

Forward Word/DOC/DOCX, Excel/XLS/XLSX and PowerPoint/PPT/PPTX-to-PDF queries are
included as **indirect informational workflows** through Google Docs, Sheets or
Slides and an authorized browser tab. These planned articles must explain native
Google/Microsoft export options and Page 2 File active-tab capture accurately;
they must not imply that Page 2 File provides a direct Office-file upload
converter.

The `PDF-HTML` cluster owns both a supplied HTML-file workflow and a clearly
separated workflow that opens a local HTML document in Chrome and captures the
rendered active tab. Developer APIs, Python libraries and reverse PDF-to-HTML
conversion remain outside this cluster.

Exclude reverse file converters, existing-PDF editing/merge/split/compression,
generic Office or Google editor navigation, generic AI/news/shopping/location
queries, developer/API tooling, native-only applications and queries without a
supported Page 2 File job to be done.

## Internal-link rule

Each article links to one product route, one hub and one to three closely
related articles. English content links only to `/en/`; Russian translations
use the identical path under `/ru/`. Product pages link back to their most
relevant articles.
